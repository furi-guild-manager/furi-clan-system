# FURI GUILD MANAGER — 퓨리 혈맹 독립 관리 시스템

현재 전달물은 **독립 웹앱의 배포 가능한 초기 소스 프로젝트(MVP)** 입니다. 이 대화에서 클라우드 계정·도메인 소유권·결제수단에 접근할 수 없으므로, 실제 인터넷 주소를 개통하거나 서버를 대신 운영 상태로 만들지는 못합니다. 대신 운영자가 소유하는 Supabase + Vercel에 배포할 수 있는 코드와 DB 구조를 제공합니다.

## 반영된 퓨리 운영 정책

- 판매금액의 20%를 혈운영비로 적립
- 나머지 80%를 실제 분배 대상자에게 1/N
- 보스 참여 5점, 공성 참여 10점
- 고가 아이템: 운영진 기준가 이상 공개 입찰
- 전체 승인 혈맹원에게 개인별 분배 내역 조회 허용
- 신규 가입은 가입 승인/등록 이후부터 참여 대상
- 회원은 삭제보다 상태 변경(활동/휴식/탈퇴/복귀) 권장
- 직책: 군주, 부군주, 간부진, 총무, 부총무, 담당자, 일반 혈맹원
- 정산 및 주요 테이블 변경 이력 저장용 audit_logs

## 기술 구성

- React + Vite + TypeScript
- Supabase Auth (아이디 + 비밀번호 로그인, 가입 승인 후 계정 발급)
- Supabase PostgreSQL + Row Level Security
- Vercel 배포 가능
- PC/스마트폰 반응형 화면

## 준비물

1. 운영진이 소유한 Supabase 계정
2. Vercel 계정
3. 퓨리 전용 도메인 (예: `guild.소유도메인` 또는 별도 도메인)
4. 운영진이 관리할 이메일 계정

도메인은 구매/소유 확인 후 DNS를 Vercel에 연결해야 합니다. 도메인명은 아직 확정되지 않았으므로 임의로 등록하지 않았습니다.

## 설치 및 배포

### 1) Supabase 프로젝트 만들기
- Supabase에서 새 프로젝트 생성
- SQL Editor에서 `supabase/schema.sql` 전체 실행
- Authentication 설정에서 공개 회원가입을 비활성화하거나, 초대 전용으로 운영
- Project Settings → API에서 Project URL과 anon/publishable key 확인

### 2) 최초 군주 계정 생성
- Supabase Authentication → Users에서 군주 이메일을 초대
- 해당 계정으로 최초 로그인 시도 후, SQL Editor에서 다음 쿼리 실행
- `YOUR_AUTH_USER_UUID`를 실제 Auth user UUID로 교체

```sql
update public.profiles
set role='군주', approved=true, display_name='퓨리 군주'
where id='YOUR_AUTH_USER_UUID';
```

### 3) 앱 환경변수 설정
프로젝트 루트에 `.env` 파일 생성:

```env
VITE_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
```

`service_role` 키는 절대 브라우저 앱에 넣지 마세요.

### 4) 로컬 실행
Node.js 20 이상 권장:

```bash
npm install
npm run dev
```

### 5) Vercel 배포
- GitHub에 이 프로젝트를 private repository로 업로드
- Vercel에서 해당 repository import
- Environment Variables에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 설정
- Build command: `npm run build`
- Output directory: `dist`
- 배포 후 Vercel 안내에 따라 퓨리 전용 도메인의 DNS 연결

## 계정 발급 및 권한

- 로그인 화면에는 아이디와 비밀번호만 입력합니다.
- 내부적으로 아이디를 `아이디@furi.invalid` 형식의 Supabase Auth 로그인 주소로 변환합니다. 실제 이메일 주소를 로그인 화면에서 요구하지 않습니다.
- 계정 발급은 Supabase Authentication에서 운영진이 사용자를 생성할 때 내부 로그인 주소를 `아이디@furi.invalid`로 입력하고 비밀번호를 지정하는 방식입니다. 이메일 확인은 이 내부 계정 방식에 맞게 비활성화해야 합니다.
- 신규 계정은 자동으로 `approved=false`, `role=member`로 생성됩니다. 최초 로그인 전/후 운영진이 프로필을 승인하고 회원과 연결해야 합니다.
- 계정의 내부 이메일 주소는 사용자에게 공유하지 않아도 됩니다.
- 군주/부군주는 앱 운영진 메뉴에서 승인 및 직책을 지정할 수 있습니다.
- 승인 전 계정은 앱 데이터에 접근할 수 없습니다.
- 초기 군주 계정은 위 SQL로 1회 지정해야 합니다.

권한 설계 요약:
- 군주/부군주: 최고 관리자
- 간부진/총무/부총무/담당자: 실무 등록 및 운영
- 일반 혈맹원: 승인된 정보 조회 및 입찰
- 분배 내역: 승인된 모든 혈맹원에게 공개

## 간편 사용 화면

- 로그인은 아이디와 비밀번호 두 칸만 사용합니다.
- 일반 혈맹원에게는 처음/보스 일정/내 기록/분배 내역 메뉴만 표시합니다.
- 운영진에게는 처음/보스 일정/혈맹원/정산·운영비/아이템 메뉴를 표시합니다.
- 큰 글씨와 큰 터치 버튼을 사용하고 스마트폰 화면을 우선 고려했습니다.

## 기존 엑셀 명단

`data/roster_import_review.csv`는 업로드된 `2.퓨리혈맹_금액분배.xlsx`의 `보스분배` 시트에서 추출한 207명 명단입니다.

**중요:** 현재 혈맹 실제 인원은 50~60명이라고 알려주셨으므로, 이 207명을 모두 활동 회원으로 자동 등록하지 않았습니다. 상태를 `검토필요`로 두었습니다. 운영진이 현재 활동/휴식/탈퇴/복귀를 대조한 뒤 Supabase Table Editor 또는 CSV import로 반영해야 합니다. 기존 엑셀의 과거 금액 기록은 별도 마이그레이션 검증 없이 현재 누적 지급액으로 합산하지 않았습니다.
